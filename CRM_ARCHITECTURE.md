# Архітектура CRM для фінансової компанії з викупу та стягнення проблемної кредитної заборгованості

Модель статусів, підстатусів, переходів, ролей, подій та аналітики.

---

## 1. Суть проблеми

Одна кредитна справа одночасно живе в кількох площинах: її можна обдзвонювати,
паралельно готувати до суду, уже мати відкриту судову справу, отримувати по ній
часткові платежі, а пізніше ще й супроводжувати у приватного виконавця.

**Ключова ідея:** не один статус на все, а кілька незалежних вимірів стану.

У справи є:
- один головний етап життєвого циклу (`global_lifecycle`)
- окремі модульні стани (кол-центр, суд, виконання)
- окремий платіжний стан (`payment_state`)
- окремі ризикові прапорці (`risk_flags`)
- окрема черга дій/SLA (`next_action`)

```

├─────────────────────────────────────────────────────┤

│  │  IMPORTED → VERIFICATION → PRE_COLLECTION    │    │
│  │  → LITIGATION → ENFORCEMENT → CLOSED/ARCHIVE │    │
│  └─────────────────────────────────────────────┘    │
│                                                     │

│  │  (0..1)      │ │  (0..1)      │ │  (0..1)    │  │
│  └──────────────┘ └──────────────┘ └────────────┘  │
│                                                     │
│  ┌─────────────────────┐ ┌─────────────────────┐   │
│  │ 5. PAYMENT STATE    │ │ RISK FLAGS (0..N)   │   │
│  │    (один)           │ │ + OPERATIONAL TAGS  │   │

│                                                     │

```

## 3. Центральні сутності системи

| Сутність | Призначення |
|----------|-------------|
| **Credit Case** | Головна сутність. Містить економіку боргу, документи, модулі, історію статусів, задачі, платежі. Може мати кілька активних модулів одночасно. |
| **Debtor** | Фізична особа: ПІБ, ІПН, контакти, адреси, ризики. Один боржник може мати кілька справ. |
| **Portfolio** | Пакет прав вимоги з параметрами придбання, KPI окупності. |
| **Claim** | Судова вимога: шаблони, документи, суми, суд, ЄСІТС-ідентифікатори. |
| **Court Proceeding** | Судова справа: номер, інстанція, стан, дати, рішення. |
| **Enforcement Proceeding** | Виконавче провадження: виконавець, регіон, ВП, дії, результат. |
| **Payment / Payment Plan** | Факти оплат, графіки, розстрочки, порушення. |
| **Task / SLA** | Конкретна дія: кому, що, до коли, пріоритет. |
| **Document** | Файл, шаблон, доказ із метаданими та версіонуванням. |
| **Event Log** | Незмінювана історія подій для доказовості та аналітики. |

## 4. Global Lifecycle

| Код | Назва | Опис |
|-----|-------|------|
| `IMPORTED` | Імпортовано | Завантажено, не перевірено |
| `VERIFICATION` | Верифікація | Перевірка даних, документів, контактів |
| `PRE_COLLECTION` | Досудова робота | Кол-центр, сегментація |
| `LITIGATION` | Суд | Позов поданий або на судовому контурі |
| `ENFORCEMENT` | Виконання | ВД в роботі у виконавця |
| `CLOSED_COLLECTED` | Закрито: стягнуто | Борг погашено |
| `CLOSED_UNCOLLECTIBLE` | Закрито: безрезультатно | Без перспективи стягнення |
| `ARCHIVED` | Архів | Для історії та звітності |

**Важливо:** якщо справа вже в Суді, але боржник платить — global lifecycle
НЕ повертається в PRE_COLLECTION. Змінюється лише payment state.

## 5. Модульні статуси

### 5.1. Кол-центр (`call_center_state`)

| Код | Назва | Опис |
|-----|-------|------|
| `NEW` | Необроблений | Не було дії оператора |
| `NO_VALID_CONTACT` | Недійсний контакт | Потрібне збагачення |
| `CALLBACK` | Передзвонити | Планова дія з датою |
| `CONTACTED` | Контакт | Був зв'язок, без результату |
| `NEGOTIATION` | Перемовини | Тривають перемовини |
| `PROMISE` | Обіцянка оплати | Заявлене зобов'язання |
| `PARTIAL_PAYMENT` | Часткова оплата | Платіж є, зобов'язання не закрито |
| `REFUSAL` | Відмова | Явна відмова |
| `DORMANT` | Без активності | Авто-тригер на перегляд |
| `STOP_CONTACT` | Контакти припинені | Заборона/спецправила |

### 5.2. Підготовка до суду (`legal_prep_state`)

| Код | Назва |
|-----|-------|
| `TO_ANALYZE` | Потребує аналізу |
| `DATA_GAP` | Брак даних/документів |
| `READY_FOR_CLAIM` | Готово до позову |
| `ON_HOLD_SETTLEMENT` | Пауза через перемовини |
| `NOT_PROFITABLE` | Недоцільно подавати |
| `APPROVED_FOR_FILING` | Погоджено подання |

### 5.3. Суд (`court_state`)

| Код | Назва |
|-----|-------|
| `DRAFTING` | Готується позов |
| `FILED` | Подано позов |
| `WITHOUT_MOTION` | Залишено без руху |
| `OPENED` | Відкрито провадження |
| `RESPONSE_RECEIVED` | Отримано відзив |
| `HEARING` | Призначено розгляд |
| `DECISION_ISSUED` | Є рішення |
| `DECISION_FINAL` | Набрало законної сили |
| `EXEC_DOC_REQUESTED` | Запитано ВД |
| `EXEC_DOC_RECEIVED` | ВД отримано |
| `APPEAL` | Апеляція |

### 5.4. Виконавче провадження (`enforcement_state`)

| Код | Назва |
|-----|-------|
| `PACKAGE_PREP` | Готується пакет |
| `SUBMITTED` | Подано ВД |
| `RETURNED_NO_OPEN` | Повернуто без відкриття |
| `OPENED` | ВП відкрито |
| `SEARCH_ASSETS` | Пошук активів |
| `GARNISHMENT` | Стягнення із зарплати/рахунків |
| `SUSPENDED` | ВП зупинене |
| `PARTIAL_RECOVERY` | Частково стягнуто |
| `CLOSED_RECOVERED` | Завершено зі стягненням |
| `CLOSED_NO_RECOVERY` | Завершено без стягнення |

## 8. Правила переходів

| Подія | Що змінює | Хто |
|-------|-----------|-----|
| Платіж отримано | `payment_state` | Автоматично |
| Гарантійний лист | `call_center_state` → PROMISE | Автоматично |
| Немає платежів > 60 днів | `payment_state` → BROKEN_INSTALLMENT + задача | Автоматично |
| Подано позов | `global_lifecycle` → LITIGATION; `court_state` → FILED | Автоматично |
| Позов без руху | `court_state` → WITHOUT_MOTION + задача юристу | Автоматично |
| ВП відкрито | `global_lifecycle` → ENFORCEMENT; `enforcement_state` → OPENED | Автоматично |
| Повне погашення | `payment_state` → FULLY_PAID; `global_lifecycle` → CLOSED_COLLECTED | Авто + підтвердження |
| Безперспективно | `global_lifecycle` → CLOSED_UNCOLLECTIBLE | Тільки вручну (керівник) |

## 9. Ролі та права

| Роль | Зона | Може | Не може |
|------|------|------|---------|
| **Директор** | Усі модулі | Усі дані, критичні статуси, масові дії | Видалення історії |
| **Оператор кол-центру** | Call-center | Дзвінки, контакти, графіки | Судові/виконавчі стани |
| **Керівник юрвідділу** | Court, legal prep | Погодження подач, контроль строків | Фінансові факти |
| **Юрист** | Court | Процесуальні документи, судові події | Закриття без погодження |
| **Керівник виконавчого** | Enforcement | Масові зміни, маршрутизація, KPI | Видалення доказів |
| **Спеціаліст виконання** | Enforcement | Ведення ВП, документи | Судові дані |
| **Документообіг** | Documents | Завантаження, реєстрація | Правова суть справи |
| **Фінансовий менеджер** | Payments | Підтвердження платежів, звіти | Судові/виконавчі стани |

## 10. Ключові метрики

| Метрика | Опис |
|---------|------|
| **Воронка** | Конверсії PRE_COLLECTION → LITIGATION → ENFORCEMENT → CLOSED_COLLECTED |
| **Aging** | Дні у кожному етапі/модулі |
| **Recovery rate** | Стягнення / баланс / вартість портфеля |
| **Promise kept rate** | Виконані обіцянки оплат |
| **Broken installment rate** | Зірвані розстрочки |
| **Executor effectiveness** | Стягнення, строк, витрати по виконавцю |
| **Court efficiency** | Виграні позови, строк отримання ВД |

## 12. Приклади багатовимірності

**Справу подано до суду, оператор продовжує дзвінки:**
- `global_lifecycle = LITIGATION`
- `call_center_state = NEGOTIATION`
- `court_state = FILED`
- `payment_state = NO_PAYMENTS`

**Боржник погодився на розстрочку після подання позову:**
- `global_lifecycle = LITIGATION`
- `payment_state = ACTIVE_INSTALLMENT`
- `call_center_state = PROMISE`

**ВД отримано, виконавець повернув без відкриття:**
- `global_lifecycle = ENFORCEMENT`
- `enforcement_state = RETURNED_NO_OPEN`
- → автоматична задача на переподання

**Боржник не платить 65 днів за розстрочкою:**
- `payment_state` → `BROKEN_INSTALLMENT` (авто)
- → повідомлення оператору та керівнику
